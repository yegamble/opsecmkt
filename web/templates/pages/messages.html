Status comes from inspecting OpenPGP packets: “to recipient’s key” means the message names a key ID from the public key the recipient had saved when it was sent. The server cannot decrypt messages and cannot confirm their contents. A message must name a key ID of the recipient’s key: the server refuses one to an account without a usable key, a passphrase-only message and one that names only other keys. “Recipient unknown” means the recipient IDs were hidden and the sender confirmed sending it; on a message stored before these checks it can also mean the recipient had no usable key or the message was passphrase-encrypted, and “NOT to recipient’s key” appears only on such older messages.

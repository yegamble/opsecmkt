## Deployment decisions

| Decision | Reason and operating consequence |
| --- | --- |
| Use the native production controller | It records the app host's endpoints, settings, keys and image digest. The legacy single-host shell installer does not provide the chosen host separation. App redeployment must preserve the existing configuration and remote services. |
| Require encryption before new native production setup | The updated controller verifies local Linux LUKS2 root and persistent runtime/input paths before staging or key generation, then rechecks saved storage identities before starts. The additional-data-disk helper does not convert a live root. All three roles have migrated state to encrypted storage and passed runtime cutover checks. Retained-copy cleanup and owner launch acceptance remain separate gates. |
| Apply a no-core policy to login sessions, services and containers | Set both soft and hard limits, including explicit root PAM rules and service drop-ins where packaged units override global defaults. Verify fresh SSH/sudo sessions, actual service processes and container processes separately. Global dump interception and initramfs policy are separate controls. |
| Make the administrator reboot control specific to the application host | A private admin request requires password, enrolled TOTP, CSRF, nonce and explicit downtime/manual-unlock acknowledgement. Its durable request and audit precede one fixed-action request to a root Unix-socket agent. New policies remain disabled until root acknowledges the real unlock/recovery rehearsal for the current OS boot. Each later boot needs a new acknowledgement. This does not supply unlock keys or maintain other hosts. |
| Create one dedicated private network and three separate compute hosts | Application, upload/scanner gateway and Monero payments have distinct roles. The gateway handles original images; database and wallet credentials stay off it. A separate maintenance worker for signed dependency reports remains pending explicit approval for its additional cost. |
| Use managed PostgreSQL 17 | Avoid operating a database VM. Fresh provider inventory confirms one online managed node; no standby or database HA is configured. The application role connected to its private endpoint with verified TLS 1.3 and UTF8. A standby is an optional additional cost requiring separate approval. Backup and restore checks remain separate. |
| Select a private direct database endpoint and verified TLS | Use a dedicated application role, the service CA and `sslmode=verify-full`. Transaction poolers require a separate compatibility review. Connection and initial schema migrations succeeded. |
| Restrict service ingress to the required private routes | Provider firewall rules restrict SSH to the approved operator source and private services to their required roles. The original-host review found no public-IP storefront listener and all 15 sampled cross-role TCP probes matched policy. All three encrypted replacements now have active, enabled host nftables policies with fresh SSH and repeat-load checks. After cutover, temporary old-peer grants were removed from the host/provider rules and managed database. Fresh old-peer denials and approved replacement paths passed. Retained original disks remain a separate exposure. |
| Generate service leaf keys on their runtime hosts and sign CSRs with a local CA | Avoid moving server leaf private keys between hosts. CA private keys remain on the issuing workstation. Runtime certificate/hostname checks and renewal tracking are still required. |
| Generate a new escrow recovery pair at the operator's request | Only the public recovery key belongs on the application host. The private half is retained on the operator workstation; confirm offline recovery storage and rehearse decryption before accepting funds. |
| Use a five-character public vanity prefix and a different authorized administrator onion | The prefix is a presentation preference. Verify the complete addresses and matching native keypairs; keep service identities separate from administrator client authorization. Public routes passed through an independent Tor circuit. The authorized administrator login form returned 200; a client without its authorization received no HTTP response. |
| Configure mainnet explicitly and keep readiness as a separate gate | Mainnet is the operator's requested network. Infrastructure creation or a running daemon cannot prove synchronization, recovery or payment readiness. No live payment result is recorded here. |
| Keep provider image backups separate from coordinated recovery | Weekly backup scheduling was activated on the original hosts. Replacement-host backups remain disabled pending separate recurring-cost approval. The provider does not encrypt these VM backups at rest; guest LUKS protects the encrypted root blocks but leaves boot material readable. No provider-image restore is proven. Retain coordinated encrypted database/wallet backups and current retention state. |
